# O0 — Full-Immersive Guardian Disable Investigation

Date: 2026-09-01

Branch: `guardian-disable-2026-09-01`

Base: `bc2ab58edadd24d8921a179a29fbe023130d13ea`

## Decision

**O0 is BLOCKED.** No tested agent-drivable control disables the safety boundary while retaining a
genuine Full (`pico.spatial.stage.style=3`) Spatial SDK world on this PICO 6.0 emulator image.

The official PICO Settings **Safeguard** toggle is agent-drivable, but it is not an effective
Full-world Guardian disable. It turns off see-through/safety-tip controls and creates a local-mode
marker. The same F1 Full route still changed from the looked Full world at the 1 m gate to looked
PICO Bedroom home pixels at the 2 m gate, both immediately and after a cold boot.

The remaining controls are owned by the production guest image:

- `sys.guardian.vst.status` remained `1`; shell `setprop` was SELinux-denied.
- `sdk_boundary_enable=129` and `sdk_boundary_GuardianSystemConfigs=13238787` both advertise
  `canWrite=0`; `PxrConfigurationService` rejected both writes.
- `adb root` reports `adbd cannot run as root in production builds` on an enforcing `user` image.
- The emulator accepts only `qemu.*` names through `-prop`; it explicitly rejected
  `sys.guardian.vst.status=0` and the guest readback remained `1`.
- No inspected Spatial SDK/OpenXR declaration provides an application boundary opt-out while
  retaining `StageStyle.Full`.

Therefore there is no no-ejection proof set. The retained captures are failure evidence, not a
substitute for the requested success. O1, O2, and O3 were not run because O0 did not succeed.

## Exact wall and what would be required

No manual-only working toggle was found either. The first still-plausible routes all require a
new privilege or vendor artifact unavailable in this production image:

1. A PICO-supported emulator launch/config option that disables Guardian before boot, or a PICO
   Settings/system service API that owns the core boundary values.
2. A debug/eng or otherwise rootable emulator image whose property policy permits changing
   `sys.guardian.vst.status`, with the consumer transition verified after the write.
3. A writable/re-signed system image changing SELinux/property ownership or
   `PxrConfigurationService` ownership for the protected `sdk_boundary_*` keys.

A broad `-selinux permissive`, writable system partition, or re-signed vendor image was not
attempted: those are image/security modifications, not a discovered Guardian control, and would
exceed the least-invasive agent path. A future privileged attempt must still prove the changed flag
and complete the same looked Full route; privilege alone is not success.
