## Result

**Positive feasibility result.** An agent traversed a genuine manifest-Full Spatial SDK world to
absolute offsets `0/1/2/4/8/16 m` by moving the complete world relative to a stationary tracked
head. Every canonical frame was LOOKed and remained inside the Full cyan corridor. The earlier
physical-walk route ejected between the 1 m and 2 m targets; this in-app route remained immersive
through 16 m while Guardian stayed active.

This is **not** a Guardian disable. It is the standard immersive-locomotion escape hatch: keep the
person's physical HMD pose inside the tracked boundary and translate the virtual world. The result
is agent-drivable through an ADB broadcast and requires no host click or privileged step.

The [O0 report](../guardian-disable-2026-09-01/O0.md) remains authoritative for the negative
Guardian-disable result. The physical-walk comparison comes from the
[CP3 F1 route](../immersive-phase1-2026-08-31/CP3.md).

## Mechanism exercised

The separately packaged throwaway probe was `com.fleet.boundarylablocomotionfull` with manifest
`pico.spatial.stage.style=3` and immersion `100`. Its debug-only implementation:

1. rendered the complete 48 m corridor as one monolithic `MeshModel` attached directly to the
   tagged `L0WorldRoot`;
2. promoted the shared `MeshResource` and `UnlitMaterial` with `toGlobal()`;
3. attached `AgentBridge.attachSceneProvider("stage") { rootRef }`;
4. intercepted the existing generic `move` builtin only for `id=L0WorldRoot`;
5. created a fresh `Entity`, `TransformComponent`, and `ModelComponent` at each requested absolute
   `+Z` offset, mounted it under the fixed SpatialView host, then detached and destroyed the old
   root; and
6. sampled `HMDTrackingProvider.latestData.hmdPose` before each renderer-grace/capture interval
   and immediately after its settled capture, bracketing the complete observation interval.

No dedicated scene-root MCP tool was added. The probe used the existing generic bridge command:
`move id=L0WorldRoot pos=0,0,<offset>`. No keyboard, controller, W/A/S/D, free-camera, or physical
walk input was sent.

The exact built APK SHA-256 was
`32a902cb89813e1c4423d46ed02c0b6d93e0565c475ca059132bc043602cbc59`. Pulling the installed
`base.apk` back to `evidence/live/installed-base.apk` produced the same hash and size 31,911,230
bytes.

### SDK surface conclusion

The public entity-transform surface for locomotion is `TransformComponent`; the successful probe
initialized each replacement root at the requested position, while `setPosition(Vector3)` is the
direct live-mutation path to test during productization. There is no public API that teleports the
tracked HMD or disables Guardian for a Full Stage. Official 0.13.3 samples demonstrate live
root/entity mutation in
`welcomespace/.../ItemDisplayVolume.kt:180`, asynchronous model attachment followed by root
transforms in `physics/.../PhysicsManager.kt:61`, and per-frame transform mutation suitable for a
continuous glide in `spatialaudio/.../FlyTrajectory.kt:52`. The resource ownership contract is
summarized in
[PICO_OFFICIAL_SAMPLES.md](../../PICO_OFFICIAL_SAMPLES.md#resource-ownership--toglobal-decides-who-closes).

Portal APIs render an independent portal world; they do not change the tracking origin and are not
a locomotion or Guardian control. The attempt-11 replacement path was retained because it was the
smallest path actually proved by rendered frames in this spike. A product implementation can test
the simpler direct root setter with the stronger presentation-readiness protocol below.

## Renderer-settlement finding

`capture_settled` tests equality between consecutive screenshots; it does not know whether an
earlier native ECS mutation has reached the renderer. An initial 1 m capture taken about 3 seconds
after the bridge acknowledgement returned the unchanged baseline SHA `c9cb98a4…`. Reissuing the
same absolute 1 m command and allowing a 10-second renderer grace produced the visibly advanced
`5d27c7ed…` frame.

The earlier attempt-7 fan-out evidence is consistent with delayed presentation: its clean changed
1 m frame was captured 7.615 seconds after acknowledgement, with no intermediate frame that could
locate the actual transition. Earlier unchanged variants remain inconclusive because they were not
rerun with a semantic wait; they are not proof that root transforms were unsupported. A productized
route should poll for a semantic transition from the prior frame, then require a stable pair,
rather than encode 10 seconds as an API guarantee.

## Deviations and negative attempts

- Attempts 1–10 exercised component replacement, direct mounted transforms, parent/root updates,
  child fan-out, monolithic transforms, fresh-root replacement, and mesh rebaking. Their unchanged
  immediate captures are inconclusive because most variants were not rerun with a semantic wait;
  attempt 7 independently established that its fan-out mutation did render. Attempt 11 combined
  correct global resource lifetime with a long enough observation window and produced the
  canonical route.
- The image viewer intermittently presented a mostly black view for the exact same
  `c9cb98a4…` source bytes that it displayed normally in other invocations. All files were still
  opened for LOOK; repeated source LOOKs and the independent review preserved the byte identity and
  visual verdict. Canonical moving frames displayed normally.
- The first attempt-11 compile referenced a nonexistent `Entity.uuid`; `pico_fix` returned only a
  generic build diagnosis. The throwaway telemetry now uses process-local identity hashes. A later
  launch-inspection shell reused zsh's special `LINES` parameter; `pico_fix` had no match and the
  read-only inspection was rerun under bash.
- The first restore launch omitted MAIN/LAUNCHER action/category and PICO kept the launcher. The
  corrected explicit MAIN/LAUNCHER new-task start cold-launched Swan Mission and restored its
  foreground activity.
- No MCP tool or registered surface changed, so no count chain was entered. No push, merge, or
  commit was performed.
- No `record_verification` receipt was created: that MCP surface was not exposed as a callable host
  tool in this agent session. The capture paths, hashes, telemetry, logs, and independent LOOK
  review are preserved here, but repository evidence remains an uncommitted documentation artifact
  rather than a registered verification record.
