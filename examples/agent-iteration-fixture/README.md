# Agent iteration fixture

A minimal PICO Spatial SDK planar app for the MCP semantic interaction loop. The debug package is `com.example.picofixture.iteration.debug`; the release package is `com.example.picofixture.iteration`. It begins with `fixture.panel` hidden and counter `0`. The allowlisted idempotent action `panel.show` with `{ "panelId": "fixture.panel" }` shows the panel and advances the state counter/revision to `1`. Repeating the desired state under a **new** request ID leaves the counter at `1`.

This is app instrumentation. It does not simulate a hand, controller, ray, click or room. Native execution and rendered acceptance remain separately gated by actual ownership and explicit emulator readiness.

Build with existing prerequisites only (including a cached wrapper distribution and dependencies):

```sh
GRADLE_USER_HOME="$PWD/.gradle-user-home" ./gradlew --offline --no-daemon -Dorg.gradle.java.installations.auto-download=false -Pandroid.builder.sdkDownload=false assembleDebug assembleRelease writeIterationInputs testDebugUnitTest
```

The official CLI generated this scaffold with Spatial SDK/BOM `6.1.9`, Kotlin `2.1.20`, Android Gradle Plugin `8.13.2` and Gradle `8.13`. The SDK selector `6.1` was resolved by the utility. See [the scaffold observation](evidence/scaffold-observation.json) for the unexpected implicit shared template refresh. No install or launch occurred during generation.

This checkout was then built using an existing absolute Gradle installation and a new project-local `.gradle-user-home` dependency cache. The exact successful offline command is in [the build record](evidence/final-offline-build.json); its dependencies were acquired into that isolated cache in an earlier authorized host build. `writeIterationInputs` records actual resolved Maven/compiler/plugin files, Gradle/JDK/build-tools/platform files and only the existing debug signing key's path/hash in the ignored `app/build/iteration-inputs.json`. This is a declared fixture input set, not a claim of a hermetic host environment or general external-module provenance.

The MCP rebuild adapter requires an explicit existing absolute `gradleExecutable` and a prepared local cache; it never bootstraps the wrapper. It seals the fixture build scripts, collects and validates that resolved report **before** compilation, retains the resulting APK immediately, and collects a second report afterward. File hashes, filesystem generations and directory membership must remain continuous through artifact retention; changing and restoring an input still invalidates the build. An explicit child environment excludes ambient JVM/Gradle injection. Project-local `gradle.properties` inside `.gradle-user-home`, init scripts, and changes to that directory's direct membership are refused. One project owner spans all phases, so concurrent calls through this adapter cannot overwrite its output. Uncertain process drain retains ownership; elapsed time does not unlock it. Manual or legacy builds remain outside that exclusion scope.

The [artifact inspection](evidence/candidate-apks.json) records both compiled APK hashes and actual merged manifests. Debug includes the bridge; release is not debuggable and its DEX files omit the bridge class, path and action. The only unprotected exported Activity is the launcher; the library profiling receiver requires `android.permission.DUMP`. The [JVM unit result](evidence/fixture-state-junit.xml) confirms the panel callback is idempotent. These are host checks; no APK has been installed or frame opened.

The debug bridge publishes bounded JSON in `files/agentbridge/interaction-v1/`. Each process creates a random app generation and separate `inbox/` and `acks/` directories. State includes package, PID/start ticks, generation and revision. The host publishes a command atomically through explicitly targeted `adb exec-out run-as`; the app consumes allowlisted messages on the main looper, writes accepted/completed/refused ACKs atomically, and retains up to 128 request IDs per generation. Duplicate IDs never execute twice. Deadlines are at most 60 seconds; the session default is 10 seconds. The host never retries a possibly applied request. Old evidence is retained; process and generation revalidation prevents its reuse.

Android's `run-as` requires the app's debuggable build. There is no exported IPC receiver or unauthenticated listener; the exported launcher Activity is the normal app entry only. This protects against another ordinary app UID. An actor already authorized to use adb `run-as` has the same debug trust boundary and can tamper with the app; the protocol does not claim cryptographic attestation against that actor. Host fixtures check shell quoting, path containment and protocol matching; actual Android access enforcement must be verified in the separately authorized runtime lane.

`AgentInteractionBridge.kt` exists only in `src/debug`. Release compiles an inert adapter. The application has no observation of secrets or arbitrary data: only its panel, counter and allowlisted action are exposed. A process restart creates fresh hidden state and a new generation without clearing app data. A harmless source edit to the title in `content/HomePage.kt` can exercise rebuild/replay, with new source and APK hashes required by the MCP.

The UI uses SpatialUI `Text` and `PicoTheme` with the native `labelPrimary` role, no custom colors or custom hover handler. The default window keeps its system `Material.Regular` glass, with no app background/border. A semantic completion still requires independent fresh state, capture and an explicit pending LOOK until someone opens and judges the image.

For the public MCP commands, finite replay/watch limits and separately gated native runbook, see [the candidate report](../../docs/findings/AGENT_ITERATION_CANDIDATE.md). From the repository root, `node scripts/agent-iteration-example.mjs describe` runs the offline stdio example.
