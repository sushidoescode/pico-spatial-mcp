### Strengths

- **The evidence rule was honoured everywhere it matters.** Nothing in code descriptions, the checkpoint, the matrix, the S6 note, the doors-transport README or the 38.0.0 receipt calls a fixture, help or source result native, visual, cross-platform or end-to-end. The receipt's `limitations` block, the matrix's "no row is native/visual", and the checkpoint's closing section all state the boundary in the same words. The three RED-phase incidents are quoted verbatim, including the irreversible logcat clears and the "I cannot claim the pipeline stopped at `devices -l`" admission.
- **The capability layer is the right shape.** `src/clicapabilities.ts` separates package activation from per-operation availability, binds every route to retained help bytes by whole-identity match, re-hashes and re-classifies stored evidence on every dispatch decision (`resolveOperationCapability`), leaves unproven shapes `unknown` rather than `unavailable`, and never derives a flag or option spelling from a version comparison. `capabilityNeedsFreshDiscovery` correctly limits re-probing to "no usable evidence" reasons so a classified `unknown` cannot become a retry loop. Every consumer (knowledge, watch, record, perf-live, four trace routes) goes through it; `preflight_env`/`pico_doctor` stay on `inspectManagedPicoCli` (read-only reuse), and discovery runs only on the lazy first CLI-backed use or `ensure_pico_cli` — consistent with the byte-pinned policy block.
- **Observation honesty is real, not decorative.** `cliobservations.ts` refuses to grade a watchdog kill `complete` on either line; `verifyapk.ts` names its device, force-stops only the package it installed, never clears logcat, attributes crashes to the PID/package, inspects the PNG before calling it a frame, re-hashes the published artifact, and chooses its status fail-closed (a missing boot id, foreground or unreadable log is `inconclusive`, never `observed`). `perfcli.ts` refuses a pre-existing report path and grades SKIP/INSUFFICIENT_DATA as `missing`; `perftrace.ts` validates the profiler envelope's resource/action/session before unwrapping rows.
- **Cross-track integration holds.** `src/preflight.ts` carries the C1 emulator-status region, the S2/S4 SDK/JDK/adb regions and the F1 fixture pins without contradiction; the adb row fails when an explicit `$PICO_ADB` does not answer, which is exactly what `src/adb.ts` makes every operation do. `src/doors.ts` carries the C4 perf axis, the C5 lanes, the C6 wording and the S5 `pico_sdk` hints coherently; the raw lane is used by exactly the two artifact-forwarding doors. `adbExecutable()` is reached lazily by every consumer (the `boundaryexperiment.ts`/`worldlocomotion.ts` module-scope resolvers were deferred to first use), so a stale `$PICO_ADB` can no longer crash startup.
- **Release machinery is now source-bound and non-destructive.** Staging→rename publication with a receipt, a bootstrap that decides on identities (and accepts npm's hidden lockfile so offline caches still start), one inventory that derives every published count, `run-gate` refusing stale `dist/`, hermetic smoke with an isolation proof, `git ls-files`-driven docs selection with containment checks, and `--publish` that can only add. Version/lock/ten manifests agree at 38.0.0 (`sync-metadata --check` clean per the ledger; verified by diff here). Every gate in `GATES` has a workflow lane; `test:runrevision` is scheduled.
- **The shipped payload is clean and provenance-recorded.** `data/sdk-compatibility` hashes match the index (`4867469d…`, `058bbf48…`), the original drift document is byte-untouched (`e1671fbd…`), the only `/Users/` string in the payload is the recorded redaction pattern whose next character is `[`, and the loader/canary validate `derivedFrom` then drop it. The three carried minors that touched code (packer wrapper duplication, `capabilityFailureClass` placement, duplicated `resolveAdb` copies, the `t.after` compiler-pid kill) were all actually closed.

#### Important (Should Fix)

Items marked **[before merge]** are cheap, and leaving them would ship a governing document or release note that is false at 38.0.0.

1. **[before merge] `AGENTS.md:29` still says the bootstrap "only builds when `dist/index.js` is absent, so a host serves a stale server forever across restarts."** R2 removed exactly that behavior (`scripts/plugin-bootstrap.mjs` now decides on source and dependency identity and rebuilds; the checkpoint's own R2 row says so). R3's ruling that "the governing doc must be true" was applied to the neighbouring paragraphs but this sentence survived. Fix: replace the clause with one sentence describing the identity-driven rebuild (outside the policy markers; the sentence carries no policy vocabulary).

2. **[before merge] `docs/findings/CLI050_IMPLEMENTATION_CHECKPOINT.md:582` lists "`npm run build` never cleans `dist/`" as a deferred minor.** It is false after R1: `publishStaging` renames the whole staging tree over `dist/` (backup, swap, remove), which is how orphans are removed. The same stale sentence is at `.claude/rules/release-invariants.md:45` (tracked). Fix: delete the clause from the checkpoint; rewrite the rules paragraph.

3. **[before merge] `docs/findings/CLI050_IMPLEMENTATION_CHECKPOINT.md:11` says "not one frame was captured or looked at."** The same document's Incident 3 records a 2,235,758-byte frame of the user's emulator written to `/tmp/pico-render/verifyapk/` and Incident 2 records `/tmp/pico-render/canonical.png` being overwritten by a real screencap. The intended claim — no frame was captured *as evidence* or looked at — is true; the literal sentence is contradicted two sections later. Fix: "no frame was captured as evidence or looked at; the only frames produced were the accidental RED-run captures recorded under Negative evidence, neither inspected nor retained."

4. **[before merge] Undisclosed default targets survive the explicit-target ruling.** `src/perfcli.ts:74,631` (`perf_diagnose`, and therefore the `pico_perf` door at `src/doors.ts:530-535`) and `src/perftrace.ts:589` (`perf_trace record`) still default `device` to `emulator-5554`. The C6 ruling (I3) made explicit target identity "a global constraint" and the checkpoint's "Known gaps carried forward" (`:557`) lists only `capture_canonical`/`pico_look`. The "Why 38.0.0" list is correctly scoped to the four tools that changed, so this is an omission rather than an over-claim — but a reader of the open items would conclude the perf lanes were covered. Fix: add a row to the known-gaps table naming `perf_diagnose`/`pico_perf` and `perf_trace record` (and, for completeness, the emulator-family tools listed in `docs/DEVICE_VERIFICATION.md` that keep the default by design). Applying the same refusal to the perf tools is a further contract break and can wait for the next surface sweep, but it must be listed.

5. **[before merge] `CHANGELOG.md` has no 38.0.0 entry.** The file states that its versions key the plugin manifests and carries a dated section per release (`## 37.0.0 — 2026-08-14` at `:32`); it was not touched on the branch. The migrations for `watchedSec`, `isError` forwarding, the `verify_pico_apk` result shape and required serial, `capture_frame`/`capture_record`/`watch_crash` explicit targets, `scaffold` refusal, fail-closed `PICO_ADB`, the build script and `--publish` file semantics exist only in the checkpoint. Fix: add a `## 38.0.0 — 2026-09-15` section that lists the compatibility-affecting changes and links the checkpoint; no policy vocabulary is needed.

6. **Residual hardcoded-0.13 editor/emulator consumers are undisclosed, and one evidence row over-scopes.** `src/editorpalette.ts:21,39` (`install_editor_palette` launches `~/Library/PICO/sdk/0.13/editor/Spatial Editor.app` unless the caller passes `editorApp`) and `src/toolchainwatch.ts:22,27` (`check_toolchain_updates` reads the 0.13 emulator `package.xml` and editor `version`) were never migrated to the S1/S2 selection. Neither appears in the checkpoint, the matrix, or the S6 note, and `evidence/…/sdk61-selection/REVIEW.md:76,84` states "every packer/editor consumer runs the SELECTED 6.1 binary on a host that also carries 0.13" — true of the consumers the named test enumerates, not of the server. `.claude/rules/src-runtime.md:10` still describes "roughly 32 sites". Fix (minimum): scope the REVIEW rows to "every consumer routed through `prepareOperationToolchain`/`resolveOperationToolchain`" and add both tools to the checkpoint's open items. Better: `editorpalette.ts` is a ten-line change to `resolveOperationToolchain({ required: ["editor"], primary: "editor" })` with the same `editorApp` override honoured as an explicit path.

7. **The `PICO_ADB` hermeticity barrier is procedural, not enforced.** The ledger's binding ruling and the checkpoint's "rule this leaves behind" require every suite run to export `PICO_ADB=/fixture/no/such/adb`, but `scripts/run-gate.mjs`, `scripts/run-battery.mjs` and `.github/workflows/gates.yml` contain no `PICO_ADB` at all (grep: zero hits). GitHub's `ubuntu-latest` image ships Android platform-tools, so a leaking test in CI would start a real adb server (no device, but not hermetic). On this host the battery was green under the pin, which proves the *current* suites; nothing stops the next one. Fix: in `runGate`, for `fixture` and `installed-artifact` scopes, default `env.PICO_ADB` to a nonexistent path under the repo (e.g. `<root>/.fixture-no-adb`) when the caller has not set it; fixtures that need their own adb already override it in the child env. Add the same env to the Linux lane in `gates.yml`. This is a one-hunk change and closes the class behind all three incidents.

8. **`src/doors.ts:369-373`: a partial injection leaves the raw-lane doors live.** `registerDoorTools(server, { call })` (the shape `test/doors.mjs:116` uses) injects only the domain lane; `doorCallRaw()` then falls back to `(await inner()).callRaw`, so `pico_look` and `pico_verify_app` on that server would spawn the real inner full-surface server — the exact bypass the C5 base RED run demonstrated. Today's tests never call a raw door on a call-only server (verified: all `pico_look`/`pico_verify_app` calls are on the `callRaw`-injected lane server or the stub-adb e2e server), so this is a latent hazard, not a defect. Fix: when `dependencies` is supplied without `callRaw`, make `doorCallRaw` reject with a fixture error instead of reaching `inner()`; the C5 ledger minor ("ignores `dependencies.call` when `callRaw` present") is the mirror of this and can be documented in the same comment.

9. **Schema-optional targets in a release whose note says "required".** `src/verifyapk.ts:135` (`serial: z.string().optional()`) and `src/picoclitools.ts:506` (`device: z.string().optional()`) describe themselves as REQUIRED while the schema says optional; the handlers refuse, so behavior is correct, and F1's ruling deferred the two one-line edits. I challenge that deferral: the 38.0.0 release note (checkpoint "Why 38.0.0") already declares "there is no default serial" for these tools, so shipping the softer schema in the same major means a schema-driven client sends nothing and learns of the break as a typed refusal instead of a validation error, and the next sweep will have to break the schema again. `watch_crash` was tightened in this round with the refusal test kept; the same two edits (plus the existing refusal tests) close it. Recommended for the fix wave; not blocking on its own because the behavior is documented.
